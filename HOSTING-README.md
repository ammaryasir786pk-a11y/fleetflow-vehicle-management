# FleetFlow online portal

The Render blueprint deploys the Express web application on the Free web service plan. PostgreSQL records and private file attachments are stored in Supabase, so they do not depend on Render's temporary filesystem. The service may sleep while idle; Supabase Free projects may pause after a week of low database activity.

## Deployment files

- `render.yaml` creates the free web service and turns on automatic deploys from the repository's `main` branch.
- `fleetflow-portal-cloud.zip` contains only application source and built public assets. It contains no user database, `.env` file, password, token, or Supabase key.

## Required service secrets

Set these in the Render service environment before the first deploy:

- `DATABASE_URL`: Supabase PostgreSQL **Session pooler** connection string, with SSL enabled.
- `SUPABASE_URL`: Supabase project URL.
- `SUPABASE_SERVICE_ROLE_KEY`: Supabase service-role secret. Never put this key into browser code or GitHub.
- `BOOTSTRAP_TOKEN`: a random secret of at least 32 characters, used only to create the first administrator.
- `JWT_SECRET` is generated by the Render blueprint.

The app creates its database tables and a private attachment bucket during startup. No desktop database or local user records are included or migrated.

After the first deploy, open `/setup` once and create the Super Admin using `BOOTSTRAP_TOKEN`. User accounts are then created from the app's Administration screen. Keep backups using the built-in backup option; free tiers do not promise production backups or uptime.

## Updating

Commit changes to the app and replace `fleetflow-portal-cloud.zip` in the public GitHub repository. Render's automatic deploy will publish that repository update.
